# Reviewer Responses — Sections 3.2 & Evidence Stage

| Reviewer Comment | Response | Proposed Improvement |
|---|---|---|
| Section 3.2 could benefit from a schema | Both knowledge bases follow a shared three-column schema: a primary label (`Event` for DNI, `Item` for Guide Terms), a `Synonyms/Keywords/Context` column for lexical expansion, and an optional `Notes` column. Each table also carries a `position` integer that encodes curation-defined ordering. | Add a small schema table to Section 3.2 showing the three columns and their types for both the DNI and Guide Terms tables. |
| Curated by who? How are clinical priorities determined? | The DNI list was curated by the clinical team at the partner care service, based on their operational definition of events that must never be omitted from a patient summary. The Care Summary Guide taxonomies were derived from the structured summary framework already in use at the service — a practitioner-facing template organising evidence into five dimensions (Outcomes, Interventions, Risks, Trends, Patterns). Both are imported as versioned CSV files for auditability. | Add one sentence attributing curation to the partner care service's clinical team and one sentence noting that the Guide taxonomies reflect the service's existing practitioner summary framework. |
| Does the Care Summary Guide follow a standard schema? | It is not a generic ontology. It reflects the specific summary structure that practitioners at this service are trained to produce and read, imported as versioned CSVs so clinical staff can propose changes without touching code. | Clarify in the text that these are service-specific, practitioner-derived taxonomies, not a published standard, and note the versioned CSV import mechanism. |
| What are "primary labels"? Risk of confusion with primary keys. | "Primary label" is used in the linguistic sense — the canonical preferred clinical phrase per row (e.g. *"fall risk"*, *"medication review"*). It also happens to serve as the database primary key for deduplication, but its role in the pipeline is purely as a surface-form string for matching. | Replace "primary labels" with "canonical terms" throughout to avoid any confusion with relational database primary keys. |
| In each table we are adding a field? | No new fields are added to taxonomy tables. The boolean flags (`deceased_flag`, `considered_disabled`, `lives_alone_flag`) are pre-existing structured columns on the `case_notes` table, ingested from source data. The pipeline *promotes* them to explicit evidence before catalogue matching to ensure they are never missed due to a text-matching failure. | Reword to: *"Structured boolean fields pre-existing on each case-note row are promoted to explicit evidence prior to catalogue matching..."* |
| Are we tokenizing? First appearance of "token" — needs clarification. | This is not linguistic tokenisation. The label is lowercased and split on any run of non-alphanumeric characters (`[^a-zA-Z0-9]+`); fragments shorter than three characters are discarded. No vocabulary, subword splits, or embeddings are involved. | On first use, replace "token" with: *"alphanumeric character-sequence produced by splitting the label on non-alphanumeric characters"*, then introduce "token" as shorthand thereafter. |
| Grammar ambiguity: "token of whose minimum length is three" reads as three tokens, not tokens of length three. | The intended meaning is each individual token must be at least 3 characters long, as confirmed by the implementation (`len(t) >= 3`). | Rewrite as: *"every alphanumeric token whose character length is at least three"*. |
| Did you mean `tok≥len(3)` or `tok≥3`? | The notation means the set of tokens from label `e` whose **character length** ≥ 3, not a count constraint. The code confirms `len(t) >= 3`. | Change notation to `tok_{\ell \geq 3}(e)` and add a one-line definition before the formula: *"Let `tok_{\ell \geq 3}(e)` denote the set of character-sequences obtained by splitting label `e` on non-alphanumeric characters and retaining only those of character length ℓ ≥ 3."* |
